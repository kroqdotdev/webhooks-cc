## Install

```bash
brew install kroqdotdev/tap/whk
# or
curl -fsSL https://webhooks.cc/install.sh | sh
# without root: any directory you can write to (created when missing)
curl -fsSL https://webhooks.cc/install.sh | WHK_INSTALL_DIR="$HOME/.local/bin" sh
```

See [all installation options](/installation) (GitHub Releases too).

## Get started

Running `whk` on its own prints the list of commands. Every command is a plain subcommand that prints text for people, or JSON with `--json`.

### Authenticate

```bash
whk auth login
```

Opens a page in your browser that shows the login's code: check that it matches the code in your terminal, and approve. Credentials are stored at `~/.config/whk/token.json`. On another machine (a server over SSH, a container), `whk` prints the link to open in your own browser instead; it notices SSH and Linux without a display by itself, and `--remote` says so outright. With `--json`, the first line carries `user_code` and `verification_url_complete` (the page with the code in it), so a program can show the link to whoever approves the login.

### Forward to localhost

```bash
whk tunnel 3000
```

Creates an endpoint, prints its URL, and forwards every incoming webhook to `localhost:3000` in real time, one line per request.

Add `--live` when the sender needs your app's response: each webhook is relayed while the sender waits ([live tunnels](/docs/live-tunnel)).

### Watch and wait

```bash
whk listen <slug>          # one line per request or email as it arrives
whk wait <slug> --since now --json   # block until the next one arrives, print it, exit
```

`whk wait` exits as soon as a matching request arrives, so a script or an agent can start it, trigger the sender, and pick up the result. Started before the sender, give it `--since now` so only a new request counts; without it, one from the last 5 minutes counts too, which suits starting it after the sender ran. Filter with `--method`, `--kind email` or `--path`, wait for several with `--count`, and set the limit with `--timeout` (30 seconds by default).

### Share a site

```bash
whk share 3000
```

Puts your local site at a public link on sharehooks.cc, for showing work in progress in a browser. See [Share localhost](/docs/share), and the [framework guides](/share#frameworks) for what Next.js, Vite, Rails, Django and others need when opened from a public name.

## Scripts, CI and AI agents

`whk` is built to be driven by programs as well as people:

- `--json` prints the API's own answers unchanged (every field the server sends), NDJSON for streams such as `listen` and `tunnel`, and failures as one `{"error": {...}}` object on stderr with a `code`, the `message`, the HTTP `status` when there was one, and a `hint` with the next step.
- Exit statuses are stable, so a script can branch on them without reading text:

| Status | Code | Meaning |
| --- | --- | --- |
| 0 | | Success |
| 1 | `error`, `bad_request` | Any other failure, or the server refused the input |
| 2 | `usage` | Bad arguments |
| 3 | `not_logged_in`, `unauthorized`, `connection_revoked`, `login_expired`, `login_denied` | No credentials, they were refused, an agent's connection was revoked, or a login code expired or was refused on its page |
| 4 | `not_found` | No such endpoint, request, team or share |
| 5 | `forbidden` | Not allowed by the plan, a limit or a permission |
| 6 | `rate_limited` | Too many requests: wait and retry |
| 7 | `server_error`, `network_error`, `request_timeout` | Our side or the network failed: retry |
| 8 | `timeout`, `approval_expired` | A wait ran out of time, or an approval was not answered in time |
| 9 | `confirmation_required`, `cancelled`, `approval_denied` | A destructive command was not confirmed, or the account's owner refused an approval |

- Nothing waits for input without a terminal. `whk delete` and `whk requests clear` ask first in a terminal; anywhere else they stop with `confirmation_required` unless you pass `--yes`.
- `whk api <path>` calls any [API route](/docs/api) with your credentials, for whatever has no command of its own yet: `whk api endpoints/<slug>/alerts`, or `whk api -X PATCH endpoints/<slug> -d '{"retentionDays":7}'`.

An agent can also capture webhooks without an account, and without a browser:

```bash
whk sandbox create --json
whk sandbox wait <slug> --json
```

`whk sandbox connect --email <address>` then prints a link and a code for its human; once they enter it, the regular commands act for their account. See [sandbox](/docs/cli/commands#sandbox) for the limits and the shared credential file.
