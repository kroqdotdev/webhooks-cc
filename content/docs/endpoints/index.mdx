## Creating an endpoint

Click **New Endpoint** in the dashboard header. Give it a name and configure an optional mock response.

Each endpoint gets an auto-generated slug that forms its webhook URL:

```
https://go.webhooks.cc/w/<slug>
```

Copy the full URL from the dashboard URL bar. Endpoints created by logged-in users, on any plan, never expire: they persist until you delete them manually or programmatically. Only ephemeral endpoints (created without an account or explicitly marked ephemeral) auto-delete after 12 hours.

## Switching endpoints

Use the endpoint switcher dropdown in the dashboard header to switch between endpoints. The request list updates in real-time when you switch.

## Sending test webhooks from the dashboard

Use the **Send** button in the URL bar to send a manual request or a signed provider template. 34 templates are available, including Stripe, GitHub, Shopify, Twilio, Square, HubSpot, Sentry, DocuSign, Adyen, PayPal, Plaid, Resend, and WorkOS.

See [Dashboard test webhook docs](/docs/endpoints/test-webhooks) for template presets, signature headers, and verification tips.

## Endpoint settings

Click the gear icon next to the endpoint name in the URL bar to open settings. You can:

- Rename the endpoint
- Configure a [mock response](/docs/mock-responses)
- [Forward](/docs/forwarding) what it captures to your servers, or [notify](/docs/notification-webhooks) a Slack or Discord channel when a request arrives
- Configure [signature verification](/docs/dashboard-features#signature-verification) — select a provider and paste your signing secret to automatically verify every incoming webhook
- Keep requests for fewer days than your plan, or only until they are delivered (see [Retention](#retention))
- Get [alerts](/docs/forwarding#alerts) when email fields stop matching, mail stops arriving or deliveries fail
- Delete the endpoint and all its captured requests

## Retention

**Settings**, **Retention** says how long the endpoint keeps what it captures:

- **Your plan's days** (the default).
- **Fewer days**: any number of days up to the plan's. Requests older than that are deleted within the hour, with their stored emails and attachments.
- **Deliver, then delete**: each request is deleted a minute after every destination has its copy or has given up, for mail you must not keep. The dashboard still shows requests as they arrive; an endpoint without destinations keeps nothing past that minute.

Through the API, `PATCH /api/endpoints/{slug}` with `retentionDays` (a number, or `null` for the plan's) and `deleteAfterDelivery`. Only the endpoint's owner can change it.

## Limits

| Plan         | Endpoints | Requests              | Retention |
| ------------ | --------- | --------------------- | --------- |
| Free         | Unlimited | 50 per 24-hour window | 7 days    |
| **Pro**      | Unlimited | 100,000 per 30 days   | 31 days   |
| **Business** | Unlimited | 250,000 per month     | 90 days   |

See [Plans & Limits](/docs/plans-limits) for full details on quotas, retention, rate limits, and billing periods.
