The [MCP server](/docs/mcp) gives a coding agent the tools. The **webhooks.cc skill** tells it what they are for and when to use them. Without it, an agent asked to "add a Stripe webhook handler" writes types from memory and often comments out the signature check to get a test passing; asked to "test the signup email", it does not know it can have a real inbox. With the skill, it knows what webhooks.cc does and picks the right tool for each job.

The skill is short on purpose, so it costs little context in every session: one `SKILL.md` of about 750 words with the essentials, and reference files the agent reads only when a task needs the detail.

## What the skill covers

| Task                                         | What the agent does                                                                                    |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Writing types for a provider's payload       | Captures real deliveries, then `generate_payload_schema` for the event in the project's language       |
| Testing a local handler                      | `send_to` with the provider, template, and your test secret; fixes raw-body parsing instead of the check |
| Adding a CI test                             | A Vitest, Jest, Playwright, pytest, or Go test with the SDKs                                           |
| Testing retries and callbacks                | Mock responses and response rules, previewed with `preview_response`, and delayed destinations          |
| Signup, magic-link, and code emails          | A tagged `{slug}+{run}@mailhooks.cc` address and `wait_for_email` for the code or link                 |
| Reading values out of emails                 | Named fields, layouts with line items and attachments, and AI setup                                    |
| Sending captures on                          | Destinations to a server, Slack, Discord, your own JSON, Google Sheets, or a file drop                 |
| A local app that needs a public URL          | `whk tunnel`, `whk tunnel --live`, and preview links with `whk share` or `share_port`                   |
| Actions you should decide                    | Shows you the link and code of an [approval](/docs/agents#approvals), then `wait_for_approval`          |
| A delivery that fails                        | `verify_signature`, `search_requests`, `compare_requests`, and `replay_request` to the local handler   |

It also tells the agent which interface fits (the remote or local MCP server, `whk` with `--json`, or an SDK in tests), how to load more [tool groups](/docs/mcp#tool-groups) when a tool is missing, what the [agent sandbox](/docs/agents) allows without an account, and a few rules: never weaken a signature check, never commit captured data, forward only to URLs you named, and stop at the plan's quota instead of retrying.

## Install with the skills CLI

Cursor, Codex, GitHub Copilot, Gemini CLI, OpenCode and most other coding agents read skills in the open `SKILL.md` format. Install it with the [skills CLI](https://github.com/vercel-labs/skills), which asks which agents to install it for:

```bash
npx skills add kroqdotdev/webhooks-cc
```

Or let the [CLI](/docs/cli) do both: `whk setup agent` writes the skill and adds the [remote server](/docs/mcp#remote-server) for every coding agent it finds on your machine ([details](/docs/cli/commands#setup-agent)).

Then add the MCP server. The [remote server](/docs/mcp#remote-server) is the easiest: add `https://webhooks.cc/mcp` to your agent's MCP settings and approve it once in your browser, with no key to paste. Or run the local server, for example:

```bash
npx @webhooks-cc/mcp setup cursor
```

For the local server the key is optional (`--api-key whcc_...`): without one it starts in the keyless sandbox, and the agent connects your account when it needs to. The [MCP server page](/docs/mcp) has the setup for each agent.

## Install in Claude Code

The plugin bundles the skill and the local MCP server, so one command sets up both:

```text
/plugin install webhooks-cc --marketplace kroqdotdev/webhooks-cc
```

On Claude Code before 2.1.275, add the marketplace first:

```text
/plugin marketplace add kroqdotdev/webhooks-cc
/plugin install webhooks-cc@webhooks-cc
```

When you enable the plugin, Claude Code asks for an API key and keeps it in your system's credential store. Leave it empty to start in the [keyless sandbox](/docs/agents): 3 endpoints for 24 hours, which Claude can connect to your account later with `connect_account`. You approve that once: the connection is saved, and later sessions start with your account's tools. To use a key instead, create one on the [API keys page](/account/api-keys).

The skill runs on its own when a task involves webhooks, test email or a public URL for a local app. To call it by name, type `/webhooks-cc:webhooks-cc`.

## From the MCP servers

Both MCP servers, the remote one at `https://webhooks.cc/mcp` and the local `@webhooks-cc/mcp`, serve the same skill to clients that support MCP skills, so such a client gets it with the server and needs no separate install.

## Install by hand

Copy [`plugins/webhooks-cc/skills/webhooks-cc`](https://github.com/kroqdotdev/webhooks-cc/tree/main/plugins/webhooks-cc/skills/webhooks-cc) into your agent's skills folder, for example `.agents/skills/` or `.claude/skills/`. Agents that discover skills on the web find it in the Agent Skills index at `https://webhooks.cc/.well-known/agent-skills/index.json`.

## For agents that read AGENTS.md

For an agent without skill support, or to make the rule hold in every session, add this to the project's `AGENTS.md` or `CLAUDE.md`:

```markdown
## Webhooks

Use webhooks.cc (the webhooks-cc MCP tools, `whk`, or `@webhooks-cc/sdk` in
tests) for webhooks, test email and public URLs for local apps. Test webhook
handlers with provider-signed payloads (the MCP tool `send_to`, or `sendTo`
in tests), never by disabling signature checks, and generate payload types
from captured requests with `generate_payload_schema`.
```

## Keep it up to date

Claude Code updates the plugin with `/plugin marketplace update webhooks-cc`. Skills installed with the skills CLI update with `npx skills update`.

The skill was called `webhook-testing` until November 2026, when it grew to cover all of webhooks.cc. If you installed it by hand or with the skills CLI under the old name, remove the `webhook-testing` folder and install it again. Links to the old files at `/.well-known/agent-skills/webhook-testing/` redirect to the new ones.
