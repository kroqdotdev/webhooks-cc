## Constructor

```ts
import { WebhooksCC } from "@webhooks-cc/sdk";

const client = new WebhooksCC({
  apiKey: string,        // Your API key. Required unless getAccessToken is given.
  getAccessToken?: (o?: { forceRefresh?: boolean }) => Promise<string>,
                         // Optional. Supplies an expiring token instead (agents).
  baseUrl?: string,      // Optional. Override API base URL.
  webhookUrl?: string,   // Optional. Override webhook receiver URL.
  timeout?: number,      // Optional. Request timeout in ms (default: 30000).
  retry?: RetryOptions,  // Optional. Automatic retry configuration.
  hooks?: ClientHooks,   // Optional. Lifecycle hooks for observability.
  emailDomain?: string,  // Optional. Domain for emails.address() (default: mailhooks.cc).
});
```

## Emails

Every endpoint on an account receives email at `<slug>@mailhooks.cc`, and at `<slug>+<tag>@mailhooks.cc` for any tag. Guest endpoints receive none. A captured email is a request with `kind: "email"`, `method: "EMAIL"`, the recipient address as `path`, the raw message as `body`, and the parsed message as `email`; the SDK types it as `EmailRequest`. Each email counts as one request against your quota. See [Email capture](/docs/email-capture) for what is stored.

Use a fresh tag per test run, so each run finds its own email:

```ts
import { extractCode } from "@webhooks-cc/sdk";

const runId = `signup-${Date.now()}`;
await signUp(client.emails.address(slug, runId)); // your app sends the email

const email = await client.emails.waitFor(slug, { tag: runId });
const code = extractCode(email); // "482913"
```

`list`, `latest`, `waitFor` and `waitForAll` filter by the same criteria. Every criterion you pass must match:

| Criterion | Type               | Matches                                                                                                           |
| --------- | ------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `tag`     | `string \| null`   | The address's `+tag`, exactly (tags are case-sensitive). `null` matches untagged mail only                        |
| `subject` | `string \| RegExp` | A string matches when the subject contains it; a RegExp is tested against the subject                             |
| `from`    | `string \| RegExp` | Any From address. A string must equal the address (case-insensitive); a RegExp is tested against `Name <address>` |
| `to`      | `string \| RegExp` | Any To or Cc address, or the address the email was delivered to, with the same rules as `from`                    |

<ApiMethod method="GET" path="(local)" title="client.emails.address">

The address an endpoint receives email at, with an optional tag. Pass the endpoint object (from `endpoints.create()` or `endpoints.get()`) to use the address the server reports; a slug builds the address with the client's `emailDomain`. Throws on an invalid slug or tag. A tag is printable ASCII without spaces, quotes, brackets, `@`, `,`, `;` or `:`, and the slug, the `+` and the tag together are at most 64 characters.

```ts
address(endpoint: string | Pick<Endpoint, "slug" | "emailAddress">, tag?: string): string
```

```ts
client.emails.address("my-app"); // "my-app@mailhooks.cc"
client.emails.address("my-app", "run-42"); // "my-app+run-42@mailhooks.cc"
```

</ApiMethod>

### Codes and links

`extractCode`, `extractLink` and `extractFromEmail` run the same finder as the dashboard's "Found in this email" strip and the `codes` and `links` of forwarded JSON. `extractCode` and `extractLink` take an `EmailRequest`, any `Request` (they return `null` for HTTP requests), or the parsed `email`; `extractFromEmail` takes the parsed `email`. None of them makes an API call.

```ts
import { extractCode, extractLink, extractFromEmail } from "@webhooks-cc/sdk";

extractCode(email); // "482913", or null
extractLink(email); // the confirm, verify, reset or sign-in link, else the first link worth keeping
extractLink(email, { actionOnly: true }); // only an action link, or null
extractFromEmail(email.email); // { codes: string[], links: { url, label, action }[] }
```

A code is only taken when a word like "code", "verification" or "sign in" sits next to it, so order numbers, prices and years stay out. See [Matchers & Helpers](/docs/sdk/matchers#email-helpers) for the rules.

### The email entry point

`@webhooks-cc/sdk/email` exports the email types, the code and link finder (`extractCode`, `extractLink`, `extractFromEmail`, `htmlToText`), `buildEmailJson`, `emailAddress` and `isValidEmailTag`. It has no network code and imports no other SDK module, so it is small enough for a browser bundle.

```ts
import { emailAddress, extractCode, type EmailReceivedEvent } from "@webhooks-cc/sdk/email";

emailAddress("my-app", "run-42"); // "my-app+run-42@mailhooks.cc"
```

## Forwarding

[Forwarding](/docs/forwarding) posts every email an endpoint captures to your server as signed `email.received` JSON, retried for about a day until your server answers 2xx. Only the endpoint's owner can manage it: for anyone else these methods throw `NotFoundError`, and `configure()` fails with a 403 for team members. Verify deliveries in your handler with [`verifyForwardedEmail()`](/docs/sdk/signatures#forwarded-emails).

```ts
await client.forwarding.configure(slug, { url: "https://example.com/hooks/email" });
const secret = await client.forwarding.secret(slug); // put it in your handler

const result = await client.forwarding.test(slug);
if (result.delivered) {
  await client.forwarding.configure(slug, { enabled: true });
}
```


## Sandbox and Agent Registration

AI agents can use webhooks.cc without an API key. `WebhooksCC.sandbox()` registers through [auth.md](/auth.md), solves the proof-of-work challenge (about 3 seconds), and returns a sandbox client: up to 3 endpoints, 25 captured requests each and 100 in all, deleted 24 hours after registration. See [AI Agents](/docs/agents) for the limits and how a human connects an agent.

<ApiMethod method="POST" path="/api/agent/identity" title="WebhooksCC.sandbox">

```ts
const sandbox = await WebhooksCC.sandbox({ clientName: "my-agent" });

const endpoint = await sandbox.endpoints.create(); // endpoint.url captures webhooks
const request = await sandbox.requests.waitFor(endpoint.slug, { timeout: "60s" });

await sandbox.endpoints.list();
await sandbox.requests.list(endpoint.slug, { limit: 10 });
await sandbox.endpoints.delete(endpoint.slug); // frees a slot; the budget is not refunded
```

Sandbox endpoints only capture: no mock responses, notifications, signature verification, email or forwarding. Refusals throw `SandboxError` with the server's `code`: `sandbox_endpoint_limit` at 3 endpoints, `sandbox_full` when the shared sandbox is full. The access token renews itself.

</ApiMethod>

<ApiMethod method="POST" path="/api/agent/identity/claim" title="sandbox.claim / sandbox.waitForClaim">

Connects the agent to a human's account. Show them the link and the code together; only someone signed in with that email can complete it.

```ts
const { verificationUri, userCode } = await sandbox.claim({ email: "dev@example.com" });
console.log(`Open ${verificationUri}, sign in, and enter ${userCode}`);

const client = await sandbox.waitForClaim(); // a WebhooksCC acting for that account
const endpoints = await client.endpoints.list(); // includes the sandbox endpoints
```

`waitForClaim()` rejects with `AgentAuthError` `expired_token` when the 15-minute code runs out (call `claim()` again for a new one), or `access_denied` when the human declines. After the claim the sandbox client stops working; the returned client renews its token from the claimed assertion for 90 days.

</ApiMethod>

<ApiMethod method="POST" path="(protocol)" title="WebhooksCC.agent">

The protocol steps one by one, for callers who drive auth.md themselves:

```ts
WebhooksCC.agent.discover({ baseUrl? })
WebhooksCC.agent.challenge()                      // a proof-of-work challenge
WebhooksCC.agent.solveChallenge(challenge, { signal? })
WebhooksCC.agent.registerAnonymous({ clientName? })   // challenge + solve + register
WebhooksCC.agent.registerServiceAuth({ email, clientName? }) // no sandbox; a human must connect it
WebhooksCC.agent.exchange({ assertion })          // one-hour access token
WebhooksCC.agent.startClaim({ claimToken, email? })
WebhooksCC.agent.pollClaim({ claimToken })
WebhooksCC.agent.waitForClaim({ claimToken, timeout? })
WebhooksCC.agent.revoke({ token })
```

The solver refuses challenges above 2^26 hashes, yields to the event loop about every 50 ms, and works in Node and browsers.

`WebhooksCC.register.*` (auth.md 0.1) is deprecated: anonymous and ID-JAG registration throw `AgentRegisterError` with code `endpoint_moved`, and the email flow stops working on November 30, 2026.

</ApiMethod>

## Matchers

Composable functions that return `(request) => boolean`. Use with `waitFor` or filter logic.

```ts
import {
  matchMethod,
  matchHeader,
  matchPath,
  matchQueryParam,
  matchBodyPath,
  matchBodySubset,
  matchContentType,
  matchJsonField,
  matchAll,
  matchAny,
  matchEmail,
  isEmailRequest,
} from "@webhooks-cc/sdk";

matchMethod("POST"); // match by HTTP method
matchHeader("x-github-event"); // match header presence
matchHeader("x-github-event", "push"); // match header value
matchPath("/webhooks/**"); // match path with glob wildcards
matchQueryParam("token"); // match query param presence
matchQueryParam("token", "abc"); // match query param value
matchBodyPath("data.object.id", "obj_123"); // match nested JSON path
matchBodySubset({ type: "checkout" }); // match deep partial subset
matchContentType("application/json"); // match content-type ignoring charset
matchJsonField("type", "checkout"); // match top-level JSON field
matchAll(matchMethod("POST"), matchHeader("stripe-signature"));
matchAny(matchMethod("GET"), matchMethod("POST"));
matchEmail({ tag: "run-42", subject: "Confirm" }); // match captured emails (see Emails)
isEmailRequest(request); // true for a captured email with its parsed message
```

`matchEmail` takes the [email criteria](#emails) and works as the `match` of `requests.waitFor()` and `captureDuring()`. It needs the parsed `email`, so it never matches requests from `subscribe()`; check `request.kind === "email"` there.


`verifyForwardedEmail` checks an email [forwarded](/docs/forwarding) to your server: the Standard Webhooks signature against the endpoint's `whsec_` secret and a timestamp within five minutes. It returns the typed `email.received` event, or throws `WebhookVerificationError` with a `code`. Pass the raw body (a string, `Uint8Array` or `ArrayBuffer`) before any JSON parsing.

```ts
verifyForwardedEmail(
  body: string | Uint8Array | ArrayBuffer,
  headers: HeadersInput,
  secret: string,
  options?: { toleranceSeconds?: number; now?: number } // defaults: 300, Date.now()
): Promise<EmailReceivedEvent>

// HeadersInput: a Fetch Headers, a plain object (Node and Express req.headers,
// array values included) or name and value pairs
type HeadersInput =
  | Headers
  | Record<string, string | string[] | undefined>
  | Iterable<readonly [string, string]>;
```

`verifyStandardWebhookSignature(body, headers, secret)` accepts the same `HeadersInput`, including a Fetch `Headers`. It checks the signature only, not the timestamp. See [Signature Verification](/docs/sdk/signatures#forwarded-emails) for a full handler.

## Error Classes

Errors include actionable recovery hints when the server message is generic.

```ts
import {
  WebhooksCCError, // Base error (has statusCode)
  UnauthorizedError, // 401: includes link to get API key
  NotFoundError, // 404: suggests using endpoints.list()
  RateLimitError, // 429: includes retryAfter seconds
```

`WebhookVerificationError.code` is `"missing_headers"`, `"timestamp_out_of_range"`, `"invalid_signature"` or `"invalid_payload"`. Answer the first three with 401 and `invalid_payload` with 400.
