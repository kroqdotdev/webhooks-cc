## Matchers

Composable functions that return `(request) => boolean`. Use with `waitFor` or filter logic.

```ts
import {
  matchMethod,
  matchHeader,
  matchPath,
  matchQueryParam,
  matchBodyPath,
  matchBodySubset,
  matchContentType,
  matchJsonField,
  matchAll,
  matchAny,
  matchEmail,
  isEmailRequest,
} from "@webhooks-cc/sdk";

matchMethod("POST"); // match by HTTP method
matchHeader("x-github-event"); // match header presence
matchHeader("x-github-event", "push"); // match header value
matchPath("/webhooks/**"); // match path with glob wildcards
matchQueryParam("token"); // match query param presence
matchQueryParam("token", "abc"); // match query param value
matchBodyPath("data.object.id", "obj_123"); // match nested JSON path
matchBodySubset({ type: "checkout" }); // match deep partial subset
matchContentType("application/json"); // match content-type ignoring charset
matchJsonField("type", "checkout"); // match top-level JSON field
matchAll(matchMethod("POST"), matchHeader("stripe-signature"));
matchAny(matchMethod("GET"), matchMethod("POST"));
matchEmail({ tag: "run-42", subject: "Confirm" }); // match captured emails (see Emails)
isEmailRequest(request); // true for a captured email with its parsed message
```

`matchEmail` takes the [email criteria](/docs/sdk/api/emails#emails) and works as the `match` of `requests.waitFor()` and `captureDuring()`. It needs the parsed `email`, so it never matches requests from `subscribe()`; check `request.kind === "email"` there.

```ts

  verifySignature,
  verifyStripeSignature,
  verifyGitHubSignature,
  verifyShopifySignature,

  verifyDiscordSignature,

  verifyGitLabSignature,
  verifyTypeformSignature,
  verifyStandardWebhookSignature,
  verifyMetaSignature,
  verifyLemonSqueezySignature,
  verifyCoinbaseCommerceSignature,
  verifyRazorpaySignature,
  verifyCalSignature,
  verifyIntercomSignature,
  verifyTelegramSignature,
  verifySquareSignature,
  verifyHubSpotSignature,
  verifyMailgunSignature,
  verifyCalendlySignature,
  verifyMuxSignature,
  verifySentrySignature,
  verifyBitbucketSignature,
  verifyDocuSignSignature,
  verifyAdyenSignature,
  verifyPayPalSignature,
  verifyResendSignature,
  verifyWorkOSSignature,
  verifyForwardedEmail,
  verifyForwardedRequest,
  verifyForwardedJson,
  verifyRelayedRequest,
} from "@webhooks-cc/sdk";

// Universal verifier (dispatches by provider)
const result = await verifySignature(request, {
  provider: "stripe",
  secret: "whsec_...",
});
console.log(result.valid); // boolean

// Provider-specific verifiers
const valid = await verifyStripeSignature(body, signatureHeader, secret);
const valid = await verifyGitHubSignature(body, signatureHeader, secret);
```

`verifyForwardedEmail` checks an email [forwarded](/docs/forwarding) to your server: the Standard Webhooks signature against the endpoint's `whsec_` secret and a timestamp within five minutes. It returns the typed `email.received` event, or throws `WebhookVerificationError` with a `code`. Pass the raw body (a string, `Uint8Array` or `ArrayBuffer`) before any JSON parsing.

```ts
verifyForwardedEmail(
  body: string | Uint8Array | ArrayBuffer,
  headers: HeadersInput,
  secret: string,
  options?: { toleranceSeconds?: number; now?: number } // defaults: 300, Date.now()
): Promise<EmailReceivedEvent>

// HeadersInput: a Fetch Headers, a plain object (Node and Express req.headers,
// array values included) or name and value pairs
type HeadersInput =
  | Headers
  | Record<string, string | string[] | undefined>
  | Iterable<readonly [string, string]>;
```

`verifyStandardWebhookSignature(body, headers, secret)` accepts the same `HeadersInput`, including a Fetch `Headers`, and the body as a string or its raw bytes (`Uint8Array` or `ArrayBuffer`). It checks the signature only, not the timestamp. See [Signature Verification](/docs/sdk/signatures#forwarded-emails) for a full handler.

## Duration Strings

`timeout` and `pollInterval` accept human-readable strings alongside milliseconds.

```
"500ms"  →    500
"30s"    →  30000
"5m"     → 300000
"1h"     → 3600000
500      →    500    // numbers passed through
```

## Error Classes

Errors include actionable recovery hints when the server message is generic.

```ts
import {
  WebhooksCCError, // Base error (has statusCode, and code when the API named one)
  UnauthorizedError, // 401: includes link to get API key
  NotFoundError, // 404: suggests using endpoints.list()
  RateLimitError, // 429: includes retryAfter seconds
  TimeoutError, // Request timeout
  WebhookVerificationError, // Thrown by verifyForwardedEmail(); has a code
} from "@webhooks-cc/sdk";
```

`WebhooksCCError.code` is the API's own error code when its answer had one, such as `"invalid_cursor"` or `"search_busy"` from `requests.searchPage()`.

`message` is what the API said as plain text (the `message` of a JSON error body, else its `error`; when that is only a code (`not_found`), the status in words, with the code in brackets when it says more (`Bad request (invalid_since)`), and `code` still holds it when it came from `error`), followed by the SDK's recovery hint when the text is short. `apiMessage` is the same text without the hint, and `path` is the API route that answered, after `/api` (such as `/endpoints/acme`); both are set on errors made from an API answer.

`WebhookVerificationError.code` is `"missing_headers"`, `"timestamp_out_of_range"`, `"invalid_signature"` or `"invalid_payload"`. Answer the first three with 401 and `invalid_payload` with 400.
