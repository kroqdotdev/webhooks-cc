## Overview

The [TypeScript SDK](/docs/sdk) wraps this API, but you can call it directly from any language using standard HTTP requests. All request and response bodies use JSON.

**Base URL:** `https://webhooks.cc`

**Webhook receiver URL:** `https://go.webhooks.cc`

**Email address:** `{slug}@mailhooks.cc` (see [Email capture](/docs/email-capture))

## Authentication

Authenticate by passing your API key in the `Authorization` header:

```
Authorization: Bearer whcc_...
```

API keys are generated from the [API keys page](/account/api-keys). Keys use the `whcc_` prefix and are stored as SHA-256 hashes; the raw key is shown only once at creation time.

<Callout type="warning">
  A few things are for the account's owner to allow. A new API key, a new share link, removing a
  custom domain, a rename, connecting a Google account, choosing a spreadsheet from Drive and AI
  setup answer an API key with `202` and an [approval](#approvals) the owner answers in the
  browser. Account deletion and changing a plan or paying take a browser session and answer `403`
  to an API key.
</Callout>

The machine-readable version of this page is the [OpenAPI document](/openapi.yaml), which lists every route below with its parameters and response shapes.

## Endpoints

### Create endpoint

```bash
curl -X POST https://webhooks.cc/api/endpoints \
  -H "Authorization: Bearer whcc_..." \
  -H "Content-Type: application/json" \
  -d '{"name": "my-endpoint"}'
```

**Response:**

```json
{
  "id": "...",
  "slug": "abc123",
  "name": "my-endpoint",
  "url": "https://go.webhooks.cc/w/abc123",
  "createdAt": 1234567890000,
  "emailAddress": "abc123@mailhooks.cc",
  "showEmailExtracts": true,
  "site": "both",
  "forwardEnabled": false,
  "forwardUrl": null,
  "hasForwardSecret": false,
  "forwardHttp": false,
  "forwardEmail": true,
  "forwardFormat": "auto",
  "forwardHeaders": [],
  "forwardAppendPath": true,
  "forwardRetrySeconds": 86400,
  "forwardKeepOrder": false,
  "forwardSentField": null
}
```

Email and forwarding fields on every endpoint:

| Field                                                  | Description                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `emailAddress`                                         | The endpoint's [email address](/docs/email-capture). `null` for guest endpoints, which receive no email.                                                                                                                                                                                                                                          |
| `showEmailExtracts`                                    | Whether codes and links found in emails are shown in the dashboard, returned by the API (`extracts`), and included in forwarded JSON. Default `true`.                                                                                                                                                                                             |
| `site`                                                 | Which site's dashboard lists the endpoint: `webhooks`, `mailhooks` or `both`. Only the listing: both addresses capture either way. Send it when creating (`both` when left out; the dashboard sends the site it is on) or updating (owner only).                                                                                                  |
| `emailFields`                                          | Named fields picked out of every email: `[{ "name", "from", "header"?, "pattern" }]`, at most 20 ([Fields you pick out](/docs/email-capture#fields-you-pick-out)). `from` is `subject`, `text`, `html`, `from`, `to` or `header`; `pattern` is RE2, its first group the value. Owner only to change; send the whole list, or `[]` to remove them. |
| `forwardEnabled`                                       | Whether captured requests are [forwarded](/docs/forwarding) to `forwardUrl`.                                                                                                                                                                                                                                                                      |
| `forwardUrl`                                           | Where requests are forwarded. Only returned to the endpoint's owner.                                                                                                                                                                                                                                                                              |
| `hasForwardSecret`                                     | Whether a forwarding secret exists. The secret itself is never included.                                                                                                                                                                                                                                                                          |
| `forwardHttp`, `forwardEmail`                          | Which kinds are forwarded: HTTP requests, emails.                                                                                                                                                                                                                                                                                                 |
| `forwardFormat`                                        | `auto` (picked from the URL), `as_received`, `json` or `chat`. See [Formats](/docs/forwarding#formats).                                                                                                                                                                                                                                           |
| `forwardHeaders`                                       | Your own headers, `[{ "name", "value" }]` with masked values. Only returned to the endpoint's owner.                                                                                                                                                                                                                                              |
| `forwardAppendPath`                                    | Whether the path after the slug is added to the URL for relayed requests.                                                                                                                                                                                                                                                                         |
| `forwardRetrySeconds`                                  | How long failed deliveries are retried: `0`, `3600` or `86400`.                                                                                                                                                                                                                                                                                   |
| `forwardKeepOrder`                                     | One delivery at a time, in capture order.                                                                                                                                                                                                                                                                                                         |
| `forwardSentField`                                     | The JSON body field holding the sender's own timestamp, or `null`. See [Timing](/docs/forwarding#timing).                                                                                                                                                                                                                                         |
| `destinationCount`                                     | How many [destinations](#destinations) the endpoint has.                                                                                                                                                                                                                                                                                          |
| `signingProvider`, `hasSigningSecret`, `signingHeader` | [Signature verification](/docs/requests#signature-verification) settings; the secret itself is never included. Send `signingProvider`, `signingSecret` and `signingHeader` (for `generic-hmac`) to change them, `null` to clear.                                                                                                                  |
| `layouts`, `layoutsCap`                                | The endpoint's [layouts](/docs/layouts) and how many of them the plan applies. Send the whole list to change it, `null` or `[]` to remove them.                                                                                                                                                                                                   |
| `retentionDays`, `retentionCapDays`                    | The endpoint's own retention in days (`null`: the plan's) and the most it can be on the plan.                                                                                                                                                                                                                                                     |
| `deleteAfterDelivery`                                  | Whether requests are deleted once every destination has them ("deliver, then delete").                                                                                                                                                                                                                                                            |

### List endpoints

```bash
curl https://webhooks.cc/api/endpoints \
  -H "Authorization: Bearer whcc_..."
```

Returns `{ "owned": [...], "shared": [...] }`: the endpoints you own, and the endpoints shared with you through a team. Each carries `favorite`, whether you marked it as a [favourite](#favourite-an-endpoint). Shared endpoints leave out `notificationUrl`, `forwardUrl` and `forwardHeaders`.

### Get endpoint

```bash
curl https://webhooks.cc/api/endpoints/abc123 \
  -H "Authorization: Bearer whcc_..."
```

### Update endpoint

Update an endpoint's name, mock response, notification webhook, signing, email, layout or retention settings. Only the fields you send change.

```bash
curl -X PATCH https://webhooks.cc/api/endpoints/abc123 \
  -H "Authorization: Bearer whcc_..." \
  -H "Content-Type: application/json" \
  -d '{"name": "new-name", "mockResponse": {"status": 200, "body": "{\"ok\":true}", "headers": {"Content-Type": "application/json"}}, "notificationUrl": "https://hooks.slack.com/services/..."}'
```

Set `"mockResponse": null` to clear the mock response and return to the default `200 OK`. Set `"notificationUrl": null` to stop sending notifications. The `notificationUrl` follows the rules of a [destination](#destinations) URL: `https` on a public host name, max 2048 characters.

Set `"showEmailExtracts": false` to stop picking out codes and links in emails. The `forward*` fields are covered under [Forwarding](#forwarding).

Team members can change `name`, `mockResponse`, and `responseRules` on shared endpoints. `showEmailExtracts`, `site`, `emailFields`, `layouts`, `retentionDays`, `deleteAfterDelivery` and the notification, signing, and forwarding settings are owner only and return `403` for anyone else, because `showEmailExtracts` also decides what forwarding sends and `site` where the endpoint is listed for everyone.

### Favourite an endpoint

Marks the endpoint as one of your favourites, which the dashboard lists first and opens by default. `DELETE` removes it again. Both are idempotent and answer `{ "favorite": true }` or `{ "favorite": false }`. A favourite is yours, not the endpoint's: team members can favourite a shared endpoint without changing it for anyone else.

```bash
curl -X PUT https://webhooks.cc/api/endpoints/abc123/favorite \
  -H "Authorization: Bearer whcc_..."

curl -X DELETE https://webhooks.cc/api/endpoints/abc123/favorite \
  -H "Authorization: Bearer whcc_..."
```

Every endpoint that List endpoints and Get endpoint return carries `favorite`, your own choice for it.

### Delete endpoint

Deletes the endpoint and all its captured requests.

```bash
curl -X DELETE https://webhooks.cc/api/endpoints/abc123 \
  -H "Authorization: Bearer whcc_..."
```

### Claim a guest endpoint

```bash
curl -X POST https://webhooks.cc/api/endpoints/claim \
  -H "Authorization: Bearer whcc_..." \
  -H "Content-Type: application/json" \
  -d '{"slug": "abc123"}'
```

Moves an endpoint made without an account (on the landing page) into yours, with the requests it has captured, and returns the endpoint. From then on it no longer expires and receives email. Returns `404` when the slug does not exist or already belongs to an account.

### Preview a response

```bash
curl -X POST https://webhooks.cc/api/endpoints/abc123/responses/preview \
  -H "Authorization: Bearer whcc_..." \
  -H "Content-Type: application/json" \
  -d '{"responseRules": [{"name": "Payment failed", "conditions": [{"field": "body_path", "op": "eq", "path": "type", "value": "payment.failed"}], "response": {"status": 402, "body": "{\"id\": \"{{ json.id }}\"}", "headers": {"Content-Type": "application/json"}}}]}'
```

Runs [response rules](/docs/mock-responses) against a captured request and fills in the placeholders, without sending anything. `mockResponse` and `responseRules` try unsaved settings; left out, the saved ones apply. `requestId` picks the request; by default it is the endpoint's newest HTTP request, or a sample when there is none. Anyone who can change the endpoint's responses can preview them. Rate limited to 120 requests per minute.

**Response:**

```json
{
  "rule": { "index": 0, "name": "Payment failed" },
  "response": {
    "status": 402,
    "headers": { "Content-Type": "application/json" },
    "body": "{\"id\": \"evt_1042\"}",
    "delay": 0
  },
  "unknownPlaceholders": [],
  "email": false,
  "request": {
    "id": "REQUEST_ID",
    "method": "POST",
    "path": "/",
    "receivedAt": 1791538201882,
    "sample": false
  }
}
```

`rule` is `null` when no rule matches and the endpoint's default response answers; `response` is `null` for the plain `200 OK`. `unknownPlaceholders` lists placeholders the receiver would send as written, which usually means a typo. `email` is `true` for an email, which gets a mail server's reply and never a mock response.

### Try layouts

```bash
curl -X POST https://webhooks.cc/api/endpoints/abc123/layouts/preview \
  -H "Authorization: Bearer whcc_..." \
  -H "Content-Type: application/json" \
  -d '{"layouts": [{"id": "acme", "name": "Acme orders", "match": {"conditions": [{"field": "email", "name": "subject", "op": "contains", "value": "Order"}]}, "fields": [{"name": "order", "from": "subject", "pattern": "#(\\d+)"}]}]}'
```

A dry run of [layouts](/docs/layouts): which one a captured email matches, and the fields and line items it finds. `layouts` tries unsaved ones (the saved ones when left out), and `requestId` picks the email (the endpoint's newest when left out). Returns `{ "problems": [...], "layoutsCap": 2, "request": { "id", "subject", "receivedAt" } | null, "parsed": { "status", "layout", "fields", "lineItems", ... } | null }`, where `parsed` is what [the result](/docs/layouts#the-result) describes. Nothing is saved and no pages are used: attachments show what an earlier parse stored, never a new one. Owner only. Rate limited to 20 requests per minute.

To save layouts, send the whole list as `layouts` in an [endpoint update](#update-endpoint).

### Add a ready-made layout

```bash
curl https://webhooks.cc/api/endpoints/abc123/layouts/template \
  -H "Authorization: Bearer whcc_..."
```

Lists the ready-made layouts as `{ "templates": [...] }`, each with `id`, `sender`, `kind` (what kind of email it reads), `description`, `fields` (the names of the fields it picks out) and `lineItems` (whether it reads line items too). The list is the same for every endpoint. To add one:

```bash
curl -X POST https://webhooks.cc/api/endpoints/abc123/layouts/template \
  -H "Authorization: Bearer whcc_..." \
  -H "Content-Type: application/json" \
  -d '{"template": "shopify-orders"}'
```

Adds one of the [ready-made layouts](/docs/layouts#ready-made-layouts) to the end of the endpoint's layouts and returns `201` with `{ "layoutId": "shopify-orders" }` (`shopify-orders-2` when that id is taken). The templates are `shopify-orders`, `woocommerce-orders`, `etsy-sales`, `amazon-seller-orders`, `ebay-sales`, `stripe-receipts`, `paypal-payments`, `booking-com-reservations`, `airbnb-reservations`, `calendly-bookings`, `form-responses`, `csv-reports` and `pdf-invoices`. Returns `400` for an unknown template or an endpoint that already has 50 layouts. Owner only.

### Alerts

```bash
curl https://webhooks.cc/api/endpoints/abc123/alerts \
  -H "Authorization: Bearer whcc_..."

curl -X PUT https://webhooks.cc/api/endpoints/abc123/alerts \
  -H "Authorization: Bearer whcc_..." \
  -H "Content-Type: application/json" \
  -d '{"enabled": true, "fieldFailures": 3, "silenceHours": 24, "destinationFailures": true}'
```

[Alerts](/docs/forwarding#alerts) tell the endpoint's owner when emails keep missing a field, when no email arrives for a while, or when a delivery failed after every retry. `GET` returns `{ "settings": {...}, "events": [...] }`, the latest 50 alerts with open ones first; `PUT` changes the settings sent, leaves the rest, and returns `{ "settings": {...} }`. Owner only.

| Setting                | Values                                                                                             |
| ---------------------- | -------------------------------------------------------------------------------------------------- |
| `enabled`              | `true` or `false` (default)                                                                        |
| `fieldFailures`        | Emails in a row that miss a required field before an alert opens: 1 to 100, or `null` for off      |
| `fieldFailureShare`    | Percent of the last 20 emails that missed one: 1 to 100, or `null` for off                         |
| `requiredFields`       | Names of the fields that must be found (at most 50), or `null` for every field                     |
| `silenceHours`         | Hours without an email before an alert opens: 1 to 720, or `null` for off                          |
| `destinationFailures`  | `true` for an alert when a delivery fails for good                                                 |
| `notifyEmail`          | `true` to email the account's address                                                              |
| `notifyDestinationIds` | Ids of this endpoint's destinations (at most 10) that also get `alert.opened` and `alert.resolved` |

Each event has `id`, `kind` (`fields`, `silence` or `destination`), `subject` (the destination, for a destination alert), `openedAt`, `resolvedAt` (`null` while open) and `details`.

## Requests

### List requests

```bash
curl "https://webhooks.cc/api/endpoints/abc123/requests?limit=50" \
  -H "Authorization: Bearer whcc_..."
```

Returns an array of request objects, newest first. Add `kind=email` for captured emails only, or `kind=http` for HTTP requests only; the paginated listing below takes the same parameter (send it on every page).

### List requests (paginated)

```bash
curl "https://webhooks.cc/api/endpoints/abc123/requests/paginated?limit=20&cursor=..." \
  -H "Authorization: Bearer whcc_..."
```

**Response:**

```json
{
  "items": [{ "id": "...", "method": "POST", "...": "..." }],
  "cursor": "eyJ...",
  "hasMore": true
}
```

Pass the returned `cursor` to the next request to fetch the next page. The cursor marks the last request on the page, so requests that arrive or are deleted while you page through never shift a page: none is skipped and none comes twice.

### Get single request

```bash
curl https://webhooks.cc/api/requests/REQUEST_ID \
  -H "Authorization: Bearer whcc_..."
```

**Response:**

```json
{
  "id": "REQUEST_ID",
  "endpointId": "...",
  "method": "POST",
  "path": "/",
  "headers": { "content-type": "application/json", "...": "..." },
  "body": "{\"event\": \"test\"}",
  "queryParams": {},
  "contentType": "application/json",
  "ip": "203.0.113.1",
  "size": 18,
  "receivedAt": 1234567890000,
  "detectedProvider": "stripe",
  "detectedEvent": "checkout.session.completed",
  "signatureVerified": true,
  "signatureError": null,
  "signingProvider": "stripe",
  "responseStatus": 402,
  "responseRule": "Payment failed",
  "kind": "http",
  "email": null,
  "liveResponse": null
}
```

`responseStatus` is the HTTP status the endpoint answered the sender with, and `responseRule` the [response rule](/docs/mock-responses) that chose it: its name, or `Rule 2` for an unnamed one by its place in the list. `responseRule` is `null` when no rule matched and the endpoint's own response or the plain 200 answered. Both are recorded when the request arrives, so later edits to the rules do not change them, and both are `null` for emails and for requests captured before answers were recorded, in November 2026.

`liveResponse` is set on HTTP requests captured while [`whk tunnel --live`](/docs/live-tunnel) relayed the endpoint to an app on someone's computer: what the sender got back, recorded once the answer finished. `responseStatus` is then that answer's status and `responseRule` is `null`, since mock responses and rules do not apply while live. It is `null` for every other request.

```json
"liveResponse": {
  "status": 200,
  "headers": { "content-type": "application/json", "x-content-type-options": "nosniff" },
  "body": "{\"received\":true}",
  "bodyTruncated": false,
  "bodyEncoding": "utf8",
  "ms": 41,
  "outcome": "answered"
}
```

| Field           | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `status`        | The status the sender got: the app's, or the stand-in's below. `null` when none was recorded.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `headers`       | The headers the sender got: the app's, without `Set-Cookie` and security headers, plus the `nosniff` and sandbox CSP headers the receiver adds.                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `body`          | The first 64 KB of the answer: text when `bodyEncoding` is `utf8`, base64 when it is `base64`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `bodyTruncated` | `true` when the answer was longer than what is kept, or was cut off past 1 MB.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `ms`            | How long the app took, in milliseconds.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `outcome`       | `answered` when the app answered. Otherwise what stood in: `offline` (502, `whk` not connected), `timeout` (504, no answer within 25 seconds), `unreachable` (502, nothing on the local port), `busy` (503 with `Retry-After`, too many relays waiting) or `refused`: the answer was not passed back as it was. `400` when the path left the endpoint; `502` when the answer was refused (a download, a script or another type an API does not answer with, or a stated size over 1 MB); or the app's own status when the answer streamed past 1 MB and was cut off, so the sender got a broken stream. |

`detectedProvider` and `detectedEvent` are best-effort metadata derived from headers and body shape. They power the provider icon and event badge in the dashboard. Signature fields are present when endpoint-level verification is configured.

`kind` is `email` for [captured emails](/docs/email-capture). Those have `method` set to `EMAIL`, the recipient address as `path`, the original message as `body`, and the parsed message (subject, addresses, text and HTML parts, attachment list, sender checks) as `email`. On an endpoint with [layouts](/docs/layouts), an email also carries `parsed`: the layout that matched, its fields, line items and parsed attachments.

Add `extracts=true` to the request list, the paginated list or a single request, and each email also carries `extracts`: the one-time codes found in it, in the order they appear, and its links, the one it asks you to click first: the same ones the dashboard shows. A signup or login test usually needs only `extracts.codes[0]` or `extracts.links[0].url`. `extracts` is `null` when the endpoint's `showEmailExtracts` is off; HTTP requests never have it. At most 20 codes and 20 links are returned. Search and the stream do not offer it.

```json
"extracts": {
  "codes": ["482913"],
  "links": [
    { "url": "https://app.example.com/confirm?token=Zk3q9v", "label": "Confirm email", "action": true }
  ]
}
```

`action` is `true` for a link that looks like what the email asks you to click (confirm, verify, reset, sign in); those come first. `label` is the link text when the link came from the HTML part, otherwise `null`.

With `extracts=true` an email also has `emailFields`, the endpoint's [named fields](/docs/email-capture#fields-you-pick-out) by name (each the text its pattern found, or `null`; `emailFields` is `null` when the endpoint has none), and `replyText`, the new text of a reply without the quoted message ([Reply text](/docs/email-capture#reply-text)). Both are there whatever `showEmailExtracts` says.

### Download the raw email

```bash
curl https://webhooks.cc/api/requests/REQUEST_ID/raw \
  -H "Authorization: Bearer whcc_..." \
  -o message.eml
```

A captured email's exact message as `message/rfc822`, byte for byte when the message was kept in object storage (`email.stored` is `true`), whatever its size. Otherwise it is the database copy, which exists for messages up to 1 MiB. Returns `400` with `{ "error": "not_an_email" }` for an HTTP request and `404` with `{ "error": "not_kept" }` when the full message was not kept. Anyone who can read the request can download it.

### Download an attachment

```bash
curl https://webhooks.cc/api/requests/REQUEST_ID/attachments/0 \
  -H "Authorization: Bearer whcc_..." \
  -o invoice.pdf
```

One attachment of a captured email as a download, by its position in `email.attachments` (from 0), with the attachment's own content type and file name. Only emails kept in object storage (`email.stored`) have their attachments' contents; for the others this returns `404` with `{ "error": "not_kept" }`.

Forwarded JSON carries attachment links of another kind, `/api/attachments/:id/:index?e=...&s=...`: those are signed, need no API key, and redirect to a short-lived download until the email passes its retention.

### Render an email

```bash
curl -X POST https://webhooks.cc/api/requests/REQUEST_ID/render \
  -H "Authorization: Bearer whcc_..." \
  -H "Content-Type: application/json" \
  -d '{"format": "postmark"}'
```

Returns a captured email the way an inbound mail service posts it, to send to the handler you wrote for that service: `{ "format", "method": "POST", "headers": { "content-type", "user-agent" }, "body" }`. `format` is `postmark`, `sendgrid` (a multipart form; the boundary is in `content-type`), `mailgun` (a form; add `"mailgunSigningKey"` to sign it the way Mailgun does), `cloudmailin`, or `json` for webhooks.cc's own `email.received` JSON, unsigned. See [In a mail provider's shape](/docs/forwarding#in-a-mail-providers-shape) for what each holds. Anyone who can read the email may render it; `400` for an HTTP request.

### Try email fields

```bash
curl -X POST https://webhooks.cc/api/endpoints/abc123/email-fields/preview \
  -H "Authorization: Bearer whcc_..." \
  -H "Content-Type: application/json" \
  -d '{"emailFields": [{"name": "invoice", "from": "subject", "pattern": "(INV-\\d+)"}]}'
```

Runs unsaved fields (or the saved ones, without `emailFields`) on the endpoint's newest email, or on `requestId`, and returns `{ "problems": [...], "request": { "id", "subject", "receivedAt" } | null, "values": { "invoice": "INV-2041" } }`. A field with a problem (a pattern RE2 cannot run) is listed in `problems` and left out of `values`. Nothing is saved. Owner only.

### Clear requests

## Forwarding

[Forwarding](/docs/forwarding) sends what an endpoint captures to up to 10 destinations: relayed as received, as signed JSON, as a JSON body you shape with placeholders, or as a chat message for Slack and Discord, each with its own conditions and timing, and retried until it is accepted. The formats and how to verify them are described in [Forwarding](/docs/forwarding). Only the endpoint's owner can configure forwarding: the owner-only routes below return `404` to anyone else, and the endpoint update returns `403`.

The `forward*` fields of an endpoint stand for its primary destination, and `notificationUrl` for a chat destination named Notifications (at most one message a second, not retried). The [destination routes](#destinations) manage all of them.

### Turn forwarding on

```bash
curl -X PATCH https://webhooks.cc/api/endpoints/abc123 \
  -H "Authorization: Bearer whcc_..." \
  -H "Content-Type: application/json" \
  -d '{"forwardUrl": "https://example.com/hooks", "forwardHttp": true, "forwardEmail": true, "forwardEnabled": true}'
```

`"forwardEnabled": true` needs a `forwardUrl`, sent in the same request or saved before. The URL must be `https` on a public host name (no IP addresses or `localhost`), max 2048 characters. Saving the first URL creates the endpoint's signing secret, so you can set up your handler and send a test delivery before turning forwarding on. Send `"forwardEnabled": false` to stop; deliveries still waiting are marked failed, and so are those of a kind you switch off. Send `"forwardUrl": null` to remove the URL once forwarding is off.

The other settings, all optional:

| Field                 | Values                                                                                                                                                                         |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `forwardHttp`         | `true` to forward HTTP requests. Default `false`.                                                                                                                              |
| `forwardEmail`        | `true` to forward emails. Default `true`.                                                                                                                                      |
| `forwardFormat`       | `auto` (default), `as_received`, `json` or `chat`.                                                                                                                             |
| `forwardHeaders`      | The whole list of your headers, at most 10: `[{ "name": "Authorization", "value": "Bearer ..." }]`. A `null` value keeps the stored value of that name; `[]` removes them all. |
| `forwardAppendPath`   | `false` to send relayed requests to the URL exactly as written. Default `true`.                                                                                                |
| `forwardRetrySeconds` | `86400` (default), `3600`, or `0` for a single try.                                                                                                                            |
| `forwardKeepOrder`    | `true` for one delivery at a time, in capture order. Default `false`.                                                                                                          |
| `forwardSentField`    | A JSON body field with the sender's timestamp, such as `publishedAt` or `data.publishedAt`; `null` clears it.                                                                  |

Returns `{ "secret": "whsec_..." }`, or `404` before a URL has been saved.

### Replay

```bash
# One request
curl -X POST https://webhooks.cc/api/requests/REQUEST_ID/replay \
  -H "Authorization: Bearer whcc_..."

# Everything an endpoint received in a time range
curl -X POST https://webhooks.cc/api/endpoints/abc123/replay \
  -H "Authorization: Bearer whcc_..." \
  -H "Content-Type: application/json" \

```

[Replay](/docs/forwarding#replay) sends captured requests through the endpoint's destinations again, with their current settings; on an endpoint with [layouts](/docs/layouts), an email is parsed again with the current layouts first. ### Destinations

```bash
curl -X POST https://webhooks.cc/api/endpoints/abc123/destinations \
  -H "Authorization: Bearer whcc_..." \
  -H "Content-Type: application/json" \

```

| Route                                              | What it does                                                                                        |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `GET /api/endpoints/:slug/destinations`            | The destinations in order, header values masked; `?summary=true` adds each one's last 24 hours      |
| `POST /api/endpoints/:slug/destinations`           | Add one (up to 10); returns it with its `id` and creates its signing secret                         |
| `GET /api/endpoints/:slug/destinations/:id`        | One destination                                                                                     |
| `PATCH /api/endpoints/:slug/destinations/:id`      | Change the fields sent; switching it off or taking a kind away fails what is waiting for it         |
| `DELETE /api/endpoints/:slug/destinations/:id`     | Remove it; what is waiting is marked failed, the log stays                                          |
| `PUT /api/endpoints/:slug/destinations/order`      | `{"ids": [...]}`, every id once: the new order                                                      |
| `GET /api/endpoints/:slug/destinations/:id/secret` | `{ "secret": "whsec_..." }`; `POST` rotates it                                                      |
| `POST /api/endpoints/:slug/destinations/:id/test`  | Send one delivery now (`kind`, `requestId`), as the forwarding test above, plus `filterPasses`      |
| `POST /api/endpoints/:slug/destinations/preview`   | Dry run: `destinationId` and/or unsaved `destination` fields, optional `requestId`; nothing is sent |

A destination's fields are `url`, `name`, `enabled`, `http`, `email`, `filter` (`{ "logic": "and" | "or", "conditions": [...] }` or `null`), `format` (`auto`, `as_received`, `json`, `template`, `chat`, or a mail provider's shape for emails: `postmark`, `sendgrid`, `mailgun`, `cloudmailin`), `bodyTemplate` (any JSON, for `template`), `messageTemplate` (for `chat`), `mailgunSigningKey` (for `mailgun`; write-only, the destination says `hasMailgunSigningKey`), `headers`, `appendPath`, `retrySeconds` (`0`, `3600` or `86400`), `keepOrder`, `sentField`, `throttleSeconds` and `delaySeconds` (0 to 3,600), `attachments` (how an email's files travel: `links`, `inline` or `none`) and `position`. #### File drops

A [file drop](/docs/forwarding#file-drops) (Business) is a destination with `"format": "file_drop"`, no `url`, its settings in `config` and its password or key in `dropSecret`:

```bash
curl -X POST https://webhooks.cc/api/endpoints/abc123/destinations \
  -H "Authorization: Bearer whcc_..." \
  -H "Content-Type: application/json" \
  -d '{"format": "file_drop", "http": false, "email": true, "name": "Orders to ERP", "config": {"protocol": "sftp", "host": "sftp.acme.example", "username": "orders", "folder": "incoming", "file": "csv", "rows": "line_items", "columns": [{"header": "Order", "value": "{{ parsed.fields.order }}"}, {"header": "SKU", "value": "{{ item.sku }}"}]}, "dropSecret": {"password": "..."}}'
```

| `config` field                                | Values                                                                                                              |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `protocol`                                    | `sftp`, `ftps`, `ftp` or `s3`                                                                                       |
| `host`, `port`, `username`                    | SFTP, FTPS and FTP: a public host name; `port` defaults to 22 (SFTP) or 21                                          |
| `endpoint`, `region`, `bucket`, `accessKeyId` | S3: the storage endpoint's URL, the region (default `us-east-1`), the bucket and the access key id                  |
| `folder`                                      | The folder (it must exist, relative to the login's home folder) or the S3 key prefix                                |
| `file`                                        | `csv` (default), `xml` or `json`                                                                                    |
| `rows`                                        | `email` (default, a row per email) or `line_items` (a row per line item)                                            |
| `columns`                                     | CSV and XML: up to 50 of `{ "header", "value" }`, the value written with placeholders                               |
| `prefix`                                      | Put before each file's name, at most 60 characters                                                                  |
| `batch`                                       | `true` for one file per batch; the destination's `delaySeconds` is the batch window                                 |
| `tlsFingerprint`                              | FTPS and S3: a self-signed certificate's SHA-256 fingerprint, then the only one accepted                            |
| `hostKey`                                     | SFTP: the server's host key fingerprint, pinned on the first connection; `null`, sent with `dropSecret`, forgets it |

`dropSecret` is `{ "password" }` (FTP, FTPS, SFTP), `{ "privateKey" }` (SFTP, OpenSSH or PEM) or `{ "secretAccessKey" }` (S3). It is stored encrypted and never returned (the destination says `hasDropSecret`), and a change to the server, login, bucket, host key or certificate fingerprint needs it sent again. The destination's test (`POST .../destinations/:id/test`) logs in and writes `webhooks-cc-test.txt`, answering `{ "ok", "file", "hostKey", "delivered", "error", ... }`. Files arrive from `mx.mailhooks.cc`.

A [Google Sheets](/docs/forwarding#google-sheets) destination has `"format": "sheets"` and `config`: `{ "connectionId", "spreadsheetId", "sheet", "rows": "email" | "line_items", "columns": [{ "header", "value" }] }`. ## Search

Search the requests you still have, across your endpoints and the endpoints a team shares with you, newest first.

```bash
curl -i "https://webhooks.cc/api/search/requests?paged=true&slug=abc123&method=POST&q=invoice&from=7d&limit=20" \
  -H "Authorization: Bearer whcc_..."
```

**Query parameters:**

| Param    | Type               | Description                                                                                                |
| -------- | ------------------ | ---------------------------------------------------------------------------------------------------------- |
| `slug`   | `string`           | Only this endpoint                                                                                         |
| `method` | `string`           | Only this HTTP method (`EMAIL` for emails)                                                                 |
| `kind`   | `string`           | `http` or `email`                                                                                          |
| `q`      | `string`           | Text to find, at most 1,000 characters (see [What a search matches](#what-a-search-matches))               |
| `from`   | `number \| string` | Start time: a Unix timestamp in ms, or a duration back from now such as `15m`, `1h`, `7d`                  |
| `to`     | `number \| string` | End time, in the same forms                                                                                |
| `limit`  | `number`           | Max results per page (default: 50, at most 200)                                                            |
| `paged`  | `boolean`          | `true` (or `1`) when you follow the cursor: each call then reads for about 2 seconds at most instead of 10 |
| `cursor` | `string`           | Continue a search from where the last page stopped (the `X-Search-Cursor` it returned)                     |
| `offset` | `number`           | Skip this many matches (at most 10,000). Prefer `cursor` to page                                           |
| `order`  | `string`           | `"desc"` (newest first, the default) or `"asc"`                                                            |

A timestamp is any number of milliseconds from zero up (a fraction is rounded down). A duration is a number and a unit: `500ms`, `90s`, `15m`, `1h`, `1.5h`, `7d`. `from=1h` means everything since an hour ago. An empty `from` or `to` sets no bound.

The response body is a JSON array of requests, as before.

### What a search matches

`q` is found as a substring, not as words: `q=voice` matches `invoice`. It is case-insensitive (a term written only in ASCII folds ASCII letters only, so the dotted capital İ and the Kelvin sign match only themselves), and every character is literal, `%`, `_` and `\` included (there are no wildcards). A request matches when the text appears in its path, its headers or its body. An email also matches on its decoded subject, its text and its from, to and cc addresses, so a message sent as base64 or quoted-printable is found by what it says. When `q` is a request id, that request comes first.

### Partial pages and the cursor

There is no text index behind search, so a search reads requests one stretch of time after another, starting at the newest (the oldest with `order=asc`). Each call reads for a limited time and then answers with what it found. It stops at whichever comes first: a full page, the end of the range, or the time limit. A common term on a busy endpoint answers in milliseconds; a rare term on a long history can return a short or empty page that is not the end.

The time limit depends on `paged`:

- **With `paged=true`**, a call reads for about 2 seconds at most, and you read on with the cursor. Use this in anything new.
- **Without it**, a call reads for about 10 seconds at most before it answers, so a client written to read one answer still reaches older matches. The headers and the cursor work the same way.

The current [SDKs](/docs/sdk/api), the [CLI](/docs/cli/commands#requests) and the [MCP server](/docs/mcp/tools#search_requests) send `paged=true` and follow the cursor, or hand it to you.

Three response headers say how far the call got:

| Header                    | Description                                                                                                                                                                                 |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-Search-Complete`       | `true` when there is nothing more to read in the range, `false` when there may be more matches                                                                                              |
| `X-Search-Searched-Until` | How far the search has read, as a Unix timestamp in ms: everything from the near end of the range to this time has been searched. Left out when a complete search had no bound on that side |
| `X-Search-Cursor`         | Send as `cursor` to continue from there. Left out when the search is complete                                                                                                               |

So an empty array with `X-Search-Complete: false` means "nothing yet, keep going", not "no matches". To read everything, repeat the call with the cursor while `X-Search-Complete` is `false`. Stop on any status other than 200, except 429: wait for `Retry-After` seconds and send the same request again.

```bash
header() { tr -d '\r' < headers.txt | awk -F': ' -v name="$1" 'tolower($1) == name { print $2 }'; }

cursor=""
while :; do
  args=(--data-urlencode "paged=true" --data-urlencode "slug=abc123" --data-urlencode "q=invoice")
  [ -n "$cursor" ] && args+=(--data-urlencode "cursor=$cursor")
  status=$(curl -s -G "https://webhooks.cc/api/search/requests" \
    -H "Authorization: Bearer whcc_..." "${args[@]}" \
    -D headers.txt -o page.json -w '%{http_code}')

  if [ "$status" = 429 ]; then
    wait=$(header retry-after)
    sleep "${wait:-5}" # then send the same request again
    continue
  fi
  if [ "$status" != 200 ]; then
    echo "search failed with status $status" >&2
    break
  fi

  cat page.json # this page's matches, possibly []
  [ "$(header x-search-complete)" = false ] || break
  cursor=$(header x-search-cursor)
  [ -n "$cursor" ] || break
done
```

Keep the other parameters the same from page to page. A cursor is opaque and belongs to the order it was made for.

Calls with a `cursor` have their own rate limit (300 per 10 minutes), apart from the 60 searches per 10 minutes that count first pages, so following one search to its end does not use up your searches.

### Search count

Count matching requests without returning them.

```bash
curl "https://webhooks.cc/api/search/requests/count?slug=abc123&method=POST" \
  -H "Authorization: Bearer whcc_..."
```

```json
{ "count": 42, "exact": true, "searchedUntil": null, "cursor": null }
```

Accepts the same query parameters as search, `paged` and `cursor` included, except `limit`, `offset` and `order`, and returns the same `X-Search-*` headers.

| Field           | Description                                                                                        |
| --------------- | -------------------------------------------------------------------------------------------------- |
| `count`         | Matches found in the part that was read                                                            |
| `exact`         | `true` when the whole range was read. `false` means the time ran out, and `count` is a lower bound |
| `searchedUntil` | How far the count read, as a Unix timestamp in ms, or `null`                                       |
| `cursor`        | Send as `cursor` to count on from there, or `null` when the count is exact                         |

A count without `q` and without `method` is always exact, for one endpoint or for all of them. A count with `q` or `method` reads requests like a search does, within the same time limit (about 2 seconds with `paged=true`, about 10 without). When `exact` is `false`, call again with `cursor`: each call counts the next stretch only, so add the counts up until `exact` is `true`. Counting on with a `cursor` has its own rate limit too (300 per 10 minutes, apart from the 120 counts).

### Search errors

| Status | `error`                           | Meaning                                                                                                                                                                               |
| ------ | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 400    | `invalid_from`, `invalid_to`      | Not a timestamp in ms (zero or more) or a duration                                                                                                                                    |
| 400    | `invalid_q`                       | The text is longer than 1,000 characters                                                                                                                                              |
| 400    | `invalid_kind`                    | Not `http` or `email`                                                                                                                                                                 |
| 400    | `invalid_limit`, `invalid_offset` | Not a number, or below zero (search only)                                                                                                                                             |
| 400    | `invalid_cursor`                  | Not a cursor this API returned, or one made for the other `order`                                                                                                                     |
| 429    | `search_busy`                     | Too many searches are running. An account runs 2 at once and the service limits how many run in all, so this can come when you run none; wait for `Retry-After` seconds and try again |
| 429    | `Too many requests`               | The [rate limit](/docs/plans-limits#rate-limits): per account and 10 minutes, 60 searches and 120 counts, and 300 calls with a `cursor` for each                                      |

## Real-time streaming (SSE)

Stream incoming requests as Server-Sent Events. Useful for building integrations that react to webhooks in real time.

```bash
curl -N "https://webhooks.cc/api/stream/abc123" \
  -H "Authorization: Bearer whcc_..." \
  -H "Accept: text/event-stream"
```

Each captured request arrives as an SSE message:

```
event: request
data: {"_id":"...","_creationTime":1234567890000,"endpointId":"...","method":"POST","path":"/","headers":{...},"body":"...","receivedAt":1234567890000,"kind":"http"}

```

The stream opens with a `connected` event (`{ "slug", "endpointId" }`). The server sends a keepalive comment (`: keepalive`) every 30 seconds to keep the connection alive. Maximum connection duration is 30 minutes: a `timeout` event comes before the stream closes, so reconnect then. `endpoint_deleted` means the endpoint is gone.

A stream message names the request id `_id` (not `id`) and has no `email` field. Emails arrive as `request` events too, with `"kind": "email"`, `"method": "EMAIL"` and the recipient address as `path`; fetch the request by its `_id` for the parsed message.

`limit` is the period's quota including monthly blocks (`blockRequests`), and `used` counts against it. `remaining` is how many more requests are accepted this period: what is left of `limit`, plus one-time blocks (`creditRequests`), plus overage up to its maximum. ## Account

### Approvals

A new API key, a new share link, removing a custom domain and a rename are the account owner's to allow. Called with an API key or an agent token, those routes answer `202` and act only once the owner approves:

```json
{
  "approval": {
    "id": "0b8d6a5e-...",
    "status": "pending",
    "action": "request_shares.create",
    "summary": "Publish a read-only copy of the request POST /stripe at a public link for 7 days.",
    "code": "ABCD-EFGH",
    "url": "https://webhooks.cc/approve?code=ABCD-EFGH",
    "expiresAt": "2026-11-14T10:15:00.000Z"
  }
}
```

Show the owner `url`; the page shows the same `code` to compare. Then poll `GET /api/approvals/:id` with the same key (or any token of the same connected agent), at most every two seconds, until `status` is `completed` (with `result`), `denied` or `expired`. A new key is made on the poll after the approval and handed over that once; the other actions run when the owner approves, and every later poll carries their `result`. The owner has 15 minutes to answer. An account can have 10 approvals waiting. See [Approvals](/docs/agents#approvals).

### API keys

`GET /api/api-keys` lists the keys (`id`, `name`, `key_prefix`, `created_at`, `expires_at`, `last_used_at`); a key itself is never shown again. `POST /api/api-keys` with `{ "name": "GitHub Actions", "expiresInDays": 90 }` (1 to 365, default 90) asks for one: the result is `{ key, name, keyPrefix, expiresAt }`. `DELETE /api/api-keys?id=<id>` revokes one.

### Display name

`PATCH /api/account` with `{ "name": "Acme Ops" }`, or `null` to clear it, asks to set the display name; the result is `{ name }`. The setting that emails the owner about approvals (`approvalEmails`) takes a browser session.

### Connected agents

`GET /api/agent/registrations` lists the agents connected to the account, claimed agents and apps connected with OAuth (`id`, `clientName`, `kind`, `connectedAt`, `lastUsedAt`). `DELETE /api/agent/registrations/:id` disconnects one with `204`: its tokens stop working at once, and the endpoints it brought stay. An agent may disconnect itself.

### Share links

A share link is a public, read-only copy of one request at `https://webhooks.cc/s/<token>` (see [Share a request](/docs/dashboard-features#share-a-request)). `GET /api/request-shares` lists the account's live links with the request each one copies; `GET /api/requests/:id/shares` lists one request's. `DELETE /api/request-shares/:id` revokes a link with `204`.

`POST /api/requests/:id/shares` with `{ "expiresInDays": 7, "hideSensitive": true }` asks for a link (1, 7 or 30 days). Credential headers are always left out, and `hideSensitive` (the default) leaves out signature and token headers too. Only the endpoint's owner can share, and emails cannot be shared. The result is `{ id, url, expiresAt, redactedHeaders }`.

### Custom domains

Business accounts and Team Business teams receive mail at [their own domains](/docs/email-capture#your-own-domain). Add `?team=<id>` to act on a team's domains (its owner only).

- `GET /api/domains` lists them with the DNS records to publish, their routes and their catch-all endpoint.
- `POST /api/domains` with `{ "domain": "mail.example.com" }` adds one and answers `201` with the records.
- `POST /api/domains/:id/verify` looks the TXT and MX records up now: `{ domain, records: { txt, mx }, tookOver }`.
- `PATCH /api/domains/:id` with `{ "catchAllEndpointId": "<id or null>", "routes": [{ "localPart": "billing", "endpointId": "<id>" }] }` replaces the routing.
- `DELETE /api/domains/:id` asks to remove it (an approval); the result is `{ removed, domainId }`.

### AI setup

`GET /api/endpoints/:slug/layouts/assist` says whether [AI setup](/docs/layouts#set-it-up-with-ai) is offered and how many assists are left: `{ offered, allowed, used, nextAt }`. `POST` with `{ "ask": { "kind": "field", "name": "order", "description": "the order number" }, "requestIds": ["..."] }` (1 to 5 of the endpoint's emails; `kind` may also be `layout` or `repair`) asks for proposals. Sending the emails to the model is the owner's consent, so with an API key it is an approval whose page lists the emails, and it runs when the owner approves; a browser session sends `"consent": true` instead. The result is `{ fields: [{ field, values }], match, layoutName, dropped, allowed, used }`. Nothing is saved: apply the fields with `PATCH /api/endpoints/:slug`.

## Routes that need a browser session

These answer `403` to an API key, because they are for a person at a browser:

- `DELETE /api/account`: delete the account and all its data
- `PATCH /api/account` with `approvalEmails`: whether approvals are emailed to the owner
- `/api/billing/*` and `/api/teams/:id/billing/*` except reads and quotes: plans, seats, extra capacity, checkout and cancellation

## Error handling

All errors return a JSON body with an `error` field:

```json
{ "error": "Invalid or missing API key" }
```

| Status | Meaning                                                                              |
| ------ | ------------------------------------------------------------------------------------ |
| `400`  | Validation error: check request body and parameters                                  |
| `401`  | Invalid or missing API key                                                           |
| `403`  | Not allowed, for example an owner-only setting                                       |
| `404`  | Resource not found                                                                   |
| `409`  | Conflict, for example redelivering with forwarding off                               |
| `429`  | Rate limited: check `Retry-After` header for wait time                               |
| `500`  | Server error                                                                         |
| `503`  | Not available here, for example [sharing](#sharing-localhost) where it is not set up |

### Rate limit headers

Rate-limited endpoints return these headers on **every** response (not just 429s):

| Header                  | Description                                     |
| ----------------------- | ----------------------------------------------- |
| `X-RateLimit-Limit`     | Maximum requests allowed in the current window  |
| `X-RateLimit-Remaining` | Remaining requests in the current window        |
| `X-RateLimit-Reset`     | Unix timestamp (seconds) when the window resets |
| `Retry-After`           | Seconds to wait (only on 429 responses)         |

```go
package main

import (
```

### Ruby

```ruby
require "net/http"
require "json"
require "uri"

API_KEY = "whcc_..."
BASE = "https://webhooks.cc"

def api_request(method, path, body = nil)
  uri = URI("#{BASE}#{path}")
  req = case method
        when :get    then Net::HTTP::Get.new(uri)
        when :post   then Net::HTTP::Post.new(uri)
        when :delete then Net::HTTP::Delete.new(uri)
        end
  req["Authorization"] = "Bearer #{API_KEY}"
  req["Content-Type"] = "application/json"
  req.body = body.to_json if body

  res = Net::HTTP.start(uri.hostname, uri.port, use_ssl: true) { |http| http.request(req) }
  JSON.parse(res.body)
end

# Create endpoint
endpoint = api_request(:post, "/api/endpoints", { name: "my-endpoint" })
slug = endpoint["slug"]
puts "Webhook URL: #{endpoint['url']}"

# Send a test webhook
api_request(:post, "/api/send-test", {
  slug: slug,
  method: "POST",
  headers: { "content-type" => "application/json" },
  body: '{"event": "test"}'
})

# List captured requests
requests = api_request(:get, "/api/endpoints/#{slug}/requests")
requests.each do |req|
  puts "#{req['method']} #{req['path']} #{req['receivedAt']}"
end
```

```rust
use reqwest::header::{AUTHORIZATION, CONTENT_TYPE, HeaderMap, HeaderValue};
use serde_json::{json, Value};

const BASE: &str = "https://webhooks.cc";
const API_KEY: &str = "whcc_...";

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let client = reqwest::Client::new();
    let mut headers = HeaderMap::new();
    headers.insert(AUTHORIZATION, HeaderValue::from_str(&format!("Bearer {API_KEY}"))?);
    headers.insert(CONTENT_TYPE, HeaderValue::from_static("application/json"));

    // Create endpoint
    let endpoint: Value = client
        .post(format!("{BASE}/api/endpoints"))
        .headers(headers.clone())
        .json(&json!({"name": "my-endpoint"}))
        .send()
        .await?
        .json()
        .await?;

    let slug = endpoint["slug"].as_str().unwrap();
    println!("Webhook URL: {}", endpoint["url"]);

    // Send a test webhook
    client
        .post(format!("{BASE}/api/send-test"))
        .headers(headers.clone())
        .json(&json!({
            "slug": slug,
            "method": "POST",
            "headers": {"content-type": "application/json"},
            "body": r#"{"event": "test"}"#
        }))
        .send()
        .await?;

    // List captured requests
    let requests: Vec<Value> = client
        .get(format!("{BASE}/api/endpoints/{slug}/requests"))
        .headers(headers)
        .send()
        .await?
        .json()
        .await?;

    for req in &requests {
        println!("{} {}", req["method"], req["path"]);
    }

    Ok(())
}
```
