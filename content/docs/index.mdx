## Get started

<Steps>
<Step title="Create an endpoint">

Sign in and click **New Endpoint** in the dashboard. Every endpoint has a URL for webhooks and an address for email:

```
https://go.webhooks.cc/w/<slug>
<slug>@mailhooks.cc
```

Or create one programmatically with the [SDK](/docs/sdk) (TypeScript, [Python](/docs/sdk/python) or [Go](/docs/sdk/go)), the [CLI](/docs/cli), or the [MCP server](/docs/mcp).

<Callout type="info">
  Endpoints made without an account (the guest URL on the home page) receive HTTP requests only.
  Sign in, on any plan, to get the email address.
</Callout>

</Step>
<Step title="Send a webhook">

Point your service at the endpoint URL. Or test it with curl:

```bash
curl -X POST https://go.webhooks.cc/w/<slug> \
  -H "Content-Type: application/json" \
  -d '{"event": "payment.success", "amount": 4999}'
```

The receiver accepts any HTTP method, content type, and body.

</Step>
<Step title="Send an email">

Send a message to `<slug>@mailhooks.cc` from any mail client, or let your app send one: sign up with that address to catch the confirmation email. Add a tag after a plus sign to tell flows apart, such as `<slug>+signup@mailhooks.cc`; it lands on the same endpoint.

An email counts as one request against your quota, like a webhook. See [Email Capture](/docs/email-capture).

</Step>
<Step title="View in the dashboard">

Open the [dashboard](/dashboard). Requests and emails appear in real time, in one list.

- **Webhooks**: inspect headers, body, query parameters, and metadata. Copy as curl, replay to another URL, or export as JSON/CSV.
- **Emails**: preview the HTML safely, copy the one-time code and main link, check the SPF, DKIM and DMARC results, and open attachments or the original message.

</Step>
</Steps>
